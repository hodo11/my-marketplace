# 순수 바닐라 웹 프레젠테이션

외부 라이브러리 없이 브라우저에서 바로 열리는 단일 `.html` 슬라이드 덱을 만든다. 파일 하나라 이메일, USB, 더블클릭으로 발표할 수 있다는 점이 핵심 가치다.

## 지원 기능

| 기능 | 동작 |
|---|---|
| 슬라이드 이동 | `→ ↓ PageDown Space` 다음, `← ↑ PageUp Shift+Space` 이전, `Home`/`End` 처음/끝 |
| 전체화면 | `F` 토글 |
| 슬라이드 번호 | 우하단 `03 / 11` 형식. 총 개수는 DOM의 `.slide` 개수로 자동 계산 |
| 부가 | 상단 진행 바, 휠, 터치 스와이프, URL 해시(`#3`)로 새로고침 시 위치 복원 |

## 작업 순서

1. **내용 파악.** 주제, 대상, 슬라이드 수, 언어, 원하는 톤을 확인한다. 사용자가 내용을 이미 줬으면 되묻지 말고 그 구조를 따른다. 부족하면 합리적으로 채우고 결과와 함께 알려 준다.
2. **템플릿 복사.** `assets/template.html`을 사용자가 원하는 위치(없으면 현재 작업 디렉터리)로 복사해 새 파일명으로 쓴다. 엔진(CSS의 `.deck`/`.slide` 규칙과 `<script>`)은 건드리지 않는다. 이미 검증된 부분이고, 번호·전체화면·키보드가 여기에 얽혀 있다.
3. **슬라이드 교체.** `<main class="deck">` 안의 `<section class="slide">`들만 내용에 맞게 바꾼다. 템플릿에 있는 컴포넌트(타이틀, 목록, 2단 카드, 터미널, 마무리)를 조합하면 대부분 충분하다.
4. **`<title>` 수정.** 브라우저 탭 제목을 발표 제목으로 바꾼다.
5. **검증.** `<script>` 본문을 `node --check`로 문법 검사한다. 가능하면 브라우저에서 열어 이동, F, 번호가 동작하는지 확인하고, 확인하지 못했다면 그렇다고 말한다.
6. **결과 보고.** 파일 경로, 슬라이드 수, 조작 키를 짧게 알린다.

## 슬라이드 작성 규칙

- **번호는 직접 쓰지 않는다.** `01 / 11` 같은 텍스트를 HTML에 넣으면 슬라이드를 추가·삭제할 때 어긋난다. 번호는 JS가 `.slide` 개수로 만든다.
- **한 슬라이드에 한 메시지.** 슬라이드는 `overflow:hidden`이고 스크롤이 없다. 내용이 넘치면 잘리므로 항목 3~5개 이하로 쓰고, 많으면 슬라이드를 나눈다.
- **`.reveal`을 요소에 붙인다.** 슬라이드에 들어올 때 순서대로 나타난다. 지연 시간은 `nth-child(1~6)`까지 정의돼 있어, 한 `.slide-content` 안에서 6개를 넘기면 뒤쪽은 같은 지연을 쓴다. 6개 초과는 피한다.
- **콘텐츠 폭은 `--content-width`(기본 680px) 안에 둔다.** 폭을 바꾸려면 토큰만 수정한다.
- 순차 등장(클릭마다 한 항목), 코드 줄 강조, 화자 노트, 가로/줌 전환, 고정 16:9 캔버스가 필요하면 `references/patterns.md`를 읽고 해당 절만 적용한다.

## 디자인 토큰

색, 폰트, 크기는 `:root`의 CSS 변수에 모여 있다. 테마(예: 라이트, 다른 액센트)를 바꿀 때는 변수만 바꾸고, 배경 그리드의 `rgba(198, 165, 92, …)`도 액센트와 맞춰 바꾼다.

기본 폰트 스택은 `'Noto Sans KR', 'Inter', sans-serif`(한글 본문)와 `'JetBrains Mono'`(코드·배지)다. Noto Sans KR에도 라틴 글리프가 있어서 이 순서에서는 영문도 Noto로 렌더된다. 영문만 Inter로 쓰고 싶다는 요청이 있으면 `@font-face`의 `unicode-range`로 분리한다.

## 왜 이런 구조인가

- **fixed + absolute, 스크롤 스냅 없음.** 스크롤 기반은 주소창, 스크롤바, 관성 때문에 슬라이드 경계가 흔들린다. `.deck`을 `fixed; inset:0`으로 두면 위아래 여백 없이 화면을 채운다.
- **상태 클래스(`is-prev`/`is-active`/`is-next`)와 `paint()` 한 곳.** 키보드, 휠, 스와이프, 해시가 모두 `goTo()`로 모이고, `paint()`가 클래스·번호·진행 바·해시를 갱신한다. 입력 경로가 늘어도 상태가 어긋나지 않는다.
- **전환 잠금 + 마지막 입력 큐잉.** 전환 중 연타해도 화면이 꼬이지 않고 마지막 목적지로 간다. 해제는 `transitionend` 대신 타이머로 한다. 탭이 숨겨지면 이벤트가 오지 않아 잠금이 영구히 걸릴 수 있기 때문이다.
- **`inert`와 `prefers-reduced-motion`.** 비활성 슬라이드는 포커스·스크린리더에서 빠지고, 모션 감소 설정이면 전환이 즉시 일어난다.

## 알려진 한계

- iPhone Safari는 문서 전체 Fullscreen API를 지원하지 않아 F가 동작하지 않는다. 오류 없이 무시된다.
- Google Fonts를 쓰므로 오프라인 발표에서는 시스템 폰트로 대체된다. 오프라인이 필수면 폰트 파일을 base64로 내장하거나 시스템 폰트 스택으로 바꾼다.
- 템플릿은 vw/rem 기반 반응형이다. 픽셀 단위 정밀도나 PDF 출력이 필요하면 `references/patterns.md`의 고정 캔버스 방식을 쓴다.
